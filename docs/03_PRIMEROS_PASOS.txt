Primer recorrido del sistema

Este recorrido permite comprobar que el código funciona antes de personalizarlo.
Usá únicamente datos ficticios mientras aprendés.

1. Entrar como administrador

Ingresá con la cuenta creada mediante createsuperuser. En Inicio verás que todavía
no hay productos. Desde Productos → Agregar producto, creá uno con nombre, tipo de
abertura y stock. En su detalle, agregá al menos un diseño.

Opcionalmente podés cargar ejemplos repetibles (reemplazá admin por tu usuario):


docker compose exec web python manage.py cargar_demo --usuario admin


Carga tres productos de ejemplo (ventana, puerta y ventiluz) con sus diseños. El
comando no sobrescribe productos existentes. No ejecutarlo sobre datos reales del cliente.

2. Solicitar una cuenta

Abrí una ventana privada del navegador. Elegí «Solicitá acceso» y completá el
formulario. Verás la confirmación de que la cuenta está pendiente. No puede entrar
todavía y no recibe permisos administrativos por registrarse.

3. Aprobar o rechazar

En la ventana del administrador, abrí «Solicitudes de acceso». Verificá la identidad
de la persona fuera del sistema y elegí «Aprobar acceso». La cuenta se convierte en
operador. La decisión y su autor se registran en el historial administrativo.

Una cuenta rechazada no puede ingresar y no se aprueba automáticamente con un
segundo envío. Para rectificar una decisión, el administrador debe revisar el caso
con el docente; no debe alterarse directamente la base ni asignar superusuario.
El panel Django Admin permite desactivar una cuenta ya aprobada desmarcando
«Puede ingresar». Esto también impide que siga accediendo con una sesión anterior.

4. Comprobar el CRUD

Con la cuenta del operador: ingresar, listar productos, buscar por nombre o tipo de
abertura, crear uno, abrir su detalle, agregarle un diseño y editarlo.

Los productos y diseños no se borran: se desactivan desmarcando «Activo» al editarlos,
para conservar los pedidos anteriores. El stock se descuenta solo cuando un pedido
pasa a producción y se devuelve si el pedido se cancela.

5. Verificar errores y conservación

- Un stock negativo debe rechazarse.
- Un producto con el mismo nombre y tipo de abertura debe mostrar un error sin duplicarse.
- Un visitante sin sesión no debe abrir los productos ni escribir enviando una URL directa.
- Después de docker compose restart, deben seguir existiendo usuario y producto.
- «Cerrar sesión» debe volver al ingreso e impedir abrir páginas protegidas.

El bloqueo del login dura 15 minutos después de cinco intentos fallidos por usuario.
El administrador del servidor puede desbloquear un caso verificado:


docker compose exec web python manage.py axes_reset_username nombre_del_usuario


Contraseñas y correo

No hay recuperación automática por correo en esta entrega. Si alguien olvida su
contraseña, el administrador comprueba su identidad y utiliza «Cambiar contraseña»
en /admin/, dentro del usuario correspondiente. No puede ver la contraseña anterior.
Cambiar una contraseña no aprueba solicitudes pendientes ni habilita usuarios desactivados.
No compartir cuentas de administrador ni incluir claves en capturas o entregas.

Para ambas modalidades

La tecnología es común. En presencial se acompaña con los entregables de arquitectura,
Docker y sprints de la comisión. En semipresencial se prioriza el proceso central y
el cronograma ajustado. El docente define las condiciones académicas; la plantilla
no determina notas ni cambia el programa. El login y los productos son el punto de
partida: cada grupo debe desarrollar y defender sus propias historias de usuario.
